Users have reported crashes while building or updating a graphify knowledge graph over corpora that contain unusual inputs: a directory accidentally passed to the file-hashing routine crashes with an uncaught error instead of being reported clearly, semantic-cache saving does the same when handed a path that no longer points to a plain file, and HTML export crashes when a graph node's source_file attribute is None rather than a string. Fix graphify/cache.py, graphify/export.py, and graphify/security.py so each of these paths degrades gracefully: file hashing should raise a clear, specific error when given something that isn't a regular file rather than an obscure OS-level exception; semantic cache saving should only attempt to save entries that are files; and label sanitization for HTML export should accept a None value and treat it as an empty string instead of crashing.
