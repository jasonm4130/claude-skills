graphify's ingest pipeline fetches tweets, web pages, and arXiv papers and writes them to disk as Markdown files with a YAML frontmatter header containing metadata (source URL, author, title, etc.) pulled directly from the fetched content. Because that metadata is interpolated into the YAML block unescaped, a title or URL containing YAML special characters can break out of its field and inject arbitrary frontmatter keys. Separately, the HTML graph export embeds node/edge/legend data as JSON inside an inline <script> tag, and a </script> sequence appearing inside a label can prematurely close the script block and inject markup into the page. Fix graphify/ingest.py so all fetched metadata values are properly escaped before being interpolated into YAML frontmatter, and fix graphify/export.py so JSON embedded in <script> tags has </ sequences escaped so they cannot terminate the tag early. While in ingest.py, also make the filename-collision-avoidance loop (which appends an incrementing counter to avoid overwriting an existing file) robust against pathological cases where it could otherwise run for a very long time.
