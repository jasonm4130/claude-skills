The dashboard's live-visitor-count widget connects to the site over a WebSocket and shows the current count as pushed by the server, but since the server only evicts stale visitors lazily (in response to new traffic), a dashboard tab left open with no further site-wide traffic keeps showing a stale, non-zero count indefinitely once the last real visitor has left. Add a periodic client-driven ping over the existing WebSocket connection so the server has a reason to recompute and push a fresh snapshot even absent new traffic. Since the connection automatically reconnects after a drop, make sure the ping timer from a previous connection is torn down when the socket closes, so reconnecting doesn't leave multiple ping loops running concurrently.
