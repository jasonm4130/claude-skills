# Nightwatch v1 batch 2: init Implementation Plan

**Goal:** a fresh Claude Code session in any repo can say "initialize nightwatch" and end up with a working, proven Nightwatch setup for that repo (clone, trust, kill switch, check command, guards, state dir, dry run), then go straight to writing specs.
**Architecture:** one Node script, `plugins/nightshift/nightwatch/init.mjs`, does every step idempotently and reports a status table; a new skill `nightwatch-init` drives it from a session (report first, one question, then run). The launcher and morning tool learn to take a repo name and read `~/.local/state/nightwatch/<name>/config`, so every later command is `run.sh <name>` / `morning.mjs <name>`. The two guards reach the unit's `claude -p` through `--settings` JSON that names the plugin's own hook files (verified 2026-09-06: a `--settings` PreToolUse hook denies a command in a headless child). The check command is the repo's `scripts/check` when it has one; otherwise init generates one in the state directory and the engine, the linter and the spec skill take the command from the config. Init therefore commits nothing, pushes nothing and opens no PR: nothing in setup or in a night touches GitHub or CI, and the only push stays the morning one.
**Tech Stack:** Node 24 stdlib `.mjs` + `node --test`; bash 3.2 + jq + git for `run.sh`; `shellcheck`; `scripts/bump-plugin.mjs`.

**Interfaces:**
- Config file `~/.local/state/nightwatch/<name>/config`, plain `KEY=value` lines, no quoting, no expansion: `NAME`, `REPO` (the working checkout `init` ran in), `ORIGIN` (its origin URL), `CLONE`, `SPECS`, `BASE` (default `main`), `STATE_VAR` (default `LANDING_STATE`), `CHECK` (the check command; `scripts/check`, or the absolute path of the generated script). `run.sh` reads it with a `while IFS== read -r k v` loop over lines matching `^[A-Z_]+=`; unknown keys are ignored.
- `run.sh <name-or-clone> [<specs-dir>] [--dry-run] [--only a,b] [--print-settings]`: when the first argument has no `/` and `$HOME/.local/state/nightwatch/<arg>/config` exists, the config supplies `CLONE`, `SPECS`, `BASE`, `STATE_VAR`, `CHECK`; an explicit second positional or an env var still wins (env > args > config). The old two-positional form keeps working unchanged. A bare name with no config exits 64 with `no config for <name>; run init.mjs` on stderr. `--print-settings` prints the exact JSON the child will get and exits 0 without touching the clone or the lock.
- The child's `--settings` JSON gains `hooks.PreToolUse` with one `Bash`-matcher entry running the two guards. Each command string is `node '<abs path>'` with the path single-quoted for the shell (a path containing a single quote is refused at startup with `STOP: plugin path contains a quote`); the absolute path is `$here/../templates/hooks/<file>.mjs` resolved with `cd … && pwd -P`. Build the JSON with `jq -n --arg`. `run.sh` exports `BASE` into the child's environment so `no-route-around-ci.mjs` protects the repo's base branch as well as `main` (confirmed by reading it: it always protects `main`, adds `BASE` from a committed `loop/config` when one exists, and adds `process.env.BASE`; `tests-are-readonly.mjs` judges the diff of the hook's cwd and needs nothing).
- The engine's `args` JSON gains `check` (from `$CHECK`); `nightwatch.mjs` uses `a.check` wherever it said `scripts/check` (Reconcile, Implement, Verify prompts and the `checkOk` description). The dry-run `finish('DRYRUN', …)` result is unchanged; `run.sh` reads it: `dry run complete` is logged only when the result's `verify.allPass` and `verify.clean` are both true, otherwise `dry run FAILED: <summary>` and the launcher exits 1 after the queue.
- Landing branch: when the local `$LANDING` exists and `git merge-base --is-ancestor "$LANDING" "origin/$BASE"` holds (nothing landed on it yet and base has moved), reset it to `origin/$BASE` and log `landing branch $LANDING moved to origin/$BASE at <sha>` before use. A landing branch with its own commits is left alone as today.
- `lint-spec.mjs --specs-dir <dir> [--check <cmd>] [file]`: the check-line rule requires an Acceptance line naming `<cmd>` whose expectation is `CHECK OK`; `run.sh` and the spec skill pass the config's `CHECK`. Default stays `scripts/check`.
- `morning.mjs <name-or-state-dir> ...`: a bare name resolves to `$HOME/.local/state/nightwatch/<name>`; `--clone` defaults to the config's `CLONE` when the config exists.

### Task 2: `init.mjs` — preflight first, every step idempotent, one status table, a dry run that proves it

**Files:**
- Create: `plugins/nightshift/nightwatch/init.mjs`.
- Test: `plugins/nightshift/tests/nightwatch-init.test.mjs` (new); `plugins/nightshift/tests/nightwatch-fixtures.mjs` (a `workingRepo(dir, { check })` helper: a temp repo whose origin is a bare repo at `<tmp>/origin/o/r.git`, one commit on `main`, optionally a `scripts/check`, plus a `.github/workflows/ci.yml` fixture with `run:` lines).

**Interfaces:**
- CLI: `node init.mjs [--repo <path>] [--name <name>] [--clone-root <dir>] [--check-cmd "<line>"]... [--set-switch] [--no-dry-run] [--report] [--json]`. Defaults: `--repo` = the git toplevel of the cwd; `--clone-root` = `$HOME/Work/Git/nightwatch`; `--name` = basename of the repo. `--report` performs no change and prints what each step would do plus the check-command suggestions. Exports `plan(opts)` → `Step[]` and `run(opts)` → `{ steps, ok }`; every subprocess (`git`, `gh`, `claude`, `run.sh`) goes through one `exec(cmd, args, opts)` wrapper (argv arrays, never a shell string) so tests shim `gh`/`claude` by `PATH`.
- Steps, each reporting `done`, `skipped (already …)`, `needs you: …`, or `failed: …`, in this order, stopping at the first `failed`. Nothing is written before step 2 passes.
  1. `preflight`: `claude`, `gh`, `jq`, `caffeinate`, `node` on PATH and `gh auth status` exit 0; each missing is `failed`. No side effects yet.
  2. `repo`: toplevel, origin URL (`git remote get-url origin`), base branch (`origin/HEAD` → its branch, else `main`), name. If `<state>/config` already exists with a different `ORIGIN`, `failed: name <name> is taken by <ORIGIN>; pass --name`. Same for an existing clone whose origin differs.
  3. `clone`: `git clone -q <origin> <clone-root>/<name>` when absent; when present, `git -C <clone> fetch -q origin` and require a clean tree (dirty → `failed: clone is dirty`).
  4. `trust`: in `$HOME/.claude.json`, set `projects[<clone>].hasTrustDialogAccepted = true`, creating `projects` and the entry when missing and preserving every other key and the entry's other fields; copy the original to `$HOME/.claude.json.nightwatch-bak` once, write atomically (temp file + rename). `skipped` when already true. A malformed file is `failed`, never overwritten. A missing file is created with just the entry.
  5. `check`: the repo has `scripts/check` → `CHECK=scripts/check`, `skipped (repo has scripts/check)`. Absent and no `--check-cmd` → `needs you: pass --check-cmd once per CI step; --report lists the candidates`, and stop before the dry run (exit 1). Absent with `--check-cmd` lines → write `<state>/check` (bash, `set -uo pipefail`; runs each line in the cwd it is invoked from, printing `✓ <line>` or `✗ <line>` plus the command's output on failure, and ends with `CHECK OK` only when every line passed; mode 755), run it once in the clone (stdin `/dev/null`, output to `<state>/check-first-run.log`) and require `CHECK OK` (failure → `failed: the check does not pass in <clone> today; see <log>`), `CHECK=<abs path>`. Re-running with new `--check-cmd` lines rewrites and re-proves the script. `--report` lists the `run:` lines from `.github/workflows/*.yml` that look like checks (fmt, clippy, test, nextest, lint, typos, machete, deny, xtask, check) as suggestions.
  6. `state`: create `<state>/{specs,dry-specs}` and write `config` (Task 1's keys, `CHECK` from step 5).
  7. `switch`: `gh variable get <STATE_VAR>` in the repo. `run` → `skipped`; otherwise with `--set-switch`, `gh variable set <STATE_VAR> --body run` (as an argv array) and re-read; without it, `needs you: run \`gh variable set LANDING_STATE --body run\` in <repo>` and continue.
  8. `dry-run` (unless `--no-dry-run`): write `<state>/dry-specs/00-plumbing.md` (title `Plumbing check`, `Repo: <name>`, Outcome "the engine can reconcile the branch and run acceptance commands in this clone", Acceptance: `git rev-parse --abbrev-ref HEAD` prints a branch starting with `nw/`; `git status --porcelain` prints nothing; `<CHECK>` prints `CHECK OK`; Non-goals: no file change; the linter must accept it with `--check <CHECK>`), then run `bash <plugin>/nightwatch/run.sh <name> <state>/dry-specs --dry-run` with stdin from `/dev/null` and the journal captured; `done` when the launcher exits 0 and the journal gains `dry run complete`, else `failed` with the journal's last `dry run` line. If the switch is not `run`, the launcher stops before the unit and the step reports `needs you: the switch is off, so the dry run did not start`.
- Output: a status table (`step  status  detail`) and a last line: `next: /nightwatch:spec` when everything is `done`/`skipped`, or the first `needs you` line. `--json` prints the steps as JSON instead. Exit 0 when nothing `failed` and the dry run ran or was skipped by flag; 1 otherwise.
