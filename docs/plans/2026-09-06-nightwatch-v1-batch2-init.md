# Nightwatch v1 batch 2: init Implementation Plan

**Goal:** a fresh Claude Code session in any repo can say "initialize nightwatch" and end up with a working, proven Nightwatch setup for that repo (clone, trust, kill switch, check command, guards, state dir, dry run), then go straight to writing specs.
**Architecture:** one Node script, `plugins/nightshift/nightwatch/init.mjs`, does every step idempotently and reports a status table; a new skill `nightwatch-init` drives it from a session (report first, one question, then run). The launcher and morning tool learn to take a repo name and read `~/.local/state/nightwatch/<name>/config`, so every later command is `run.sh <name>` / `morning.mjs <name>`. The two guards reach the unit's `claude -p` through `--settings` JSON that names the plugin's own hook files (verified today: a `--settings` PreToolUse hook denies a command in a headless child), so a repo commits nothing for Nightwatch except a `scripts/check` when it has no check command.
**Tech Stack:** Node 24 stdlib `.mjs` + `node --test`; bash 3.2 + jq + git for `run.sh`; `shellcheck`; `scripts/bump-plugin.mjs`.

**Interfaces:**
- Config file `~/.local/state/nightwatch/<name>/config`, plain `KEY=value` lines, no quoting, no expansion: `NAME`, `REPO` (the working checkout `init` ran in), `CLONE`, `SPECS`, `BASE` (default `main`), `STATE_VAR` (default `LANDING_STATE`), `CHECK` (the check command, default `scripts/check`). `run.sh` reads it with a `while IFS== read -r k v` loop over lines matching `^[A-Z_]+=`; unknown keys are ignored.
- `run.sh <name-or-clone> [<specs-dir>] [--dry-run] [--only a,b] [--print-settings]`: when the first argument has no `/` and `$HOME/.local/state/nightwatch/<arg>/config` exists, the config supplies `CLONE`, `SPECS`, `BASE`, `STATE_VAR`; an explicit second positional or an env var still wins (env > args > config). The old two-positional form keeps working unchanged. `--print-settings` prints the exact JSON the child will get and exits 0 without touching the clone or the lock.
- The child's `--settings` JSON gains `hooks.PreToolUse` with one `Bash`-matcher entry running `node <plugin>/templates/hooks/no-route-around-ci.mjs` and `node <plugin>/templates/hooks/tests-are-readonly.mjs` by absolute path (`$here/../templates/hooks/...`, resolved with `cd … && pwd`), alongside the existing `env` override. Build the JSON with `jq -n --arg` so paths with spaces survive. A project's own hooks still load (the clone is trusted); these add to them.
- `morning.mjs <name-or-state-dir> ...`: a bare name resolves to `$HOME/.local/state/nightwatch/<name>`; `--clone` defaults to the config's `CLONE` when the config exists.
- Both guards already work outside a loop-initialised repo (confirmed by reading them): `no-route-around-ci.mjs` always protects `main`, adds `BASE` from the committed `loop/config` when one exists, and adds `process.env.BASE` when set; `tests-are-readonly.mjs` judges the staged and unstaged diff of the hook's cwd. `run.sh` therefore exports `BASE` into the child's environment (it already passes the base to the engine) so a repo whose base is not `main` is protected too.

### Task 2: `init.mjs` — every step idempotent, one status table, a dry run at the end

**Files:**
- Create: `plugins/nightshift/nightwatch/init.mjs`.
- Test: `plugins/nightshift/tests/nightwatch-init.test.mjs` (new); `plugins/nightshift/tests/nightwatch-fixtures.mjs` (a `workingRepo()` helper: a temp repo with a bare origin under `github.com/o/r.git`, one commit on `main`, optionally a `scripts/check`, plus a `.github/workflows/ci.yml` fixture with `run:` lines).

**Interfaces:**
- CLI: `node init.mjs [--repo <path>] [--clone-root <dir>] [--check-cmd "<line>"]... [--set-switch] [--no-dry-run] [--report] [--json]`. Defaults: `--repo` = the git toplevel of the cwd; `--clone-root` = `$HOME/Work/Git/nightwatch`; name = basename of the repo. `--report` performs no change and prints what each step would do. Exports `plan(opts)` → `Step[]` and `run(opts)` → `{ steps, ok }` so the test needs no subprocess for the logic; the subprocess-shaped calls (`git`, `gh`, `claude`, `run.sh`) go through one `exec(cmd, args, opts)` wrapper so the test can shim them by `PATH`.
- Steps, each reporting `done`, `skipped (already …)`, `needs you: …`, or `failed: …`, in this order, stopping at the first `failed`:
  1. `repo`: toplevel, origin URL (`git remote get-url origin`), base branch (`origin/HEAD` → `refs/remotes/origin/<b>`, else `main`), name.
  2. `clone`: `git clone <origin> <clone-root>/<name>` when absent (quiet); when present, `git -C <clone> fetch -q origin` and require a clean tree (dirty → `failed: clone is dirty`). Origin of an existing clone must match the repo's origin URL, else `failed`.
  3. `trust`: in `$HOME/.claude.json`, set `projects[<clone>].hasTrustDialogAccepted = true`, creating `projects` and the entry when missing and preserving every other key and the existing entry's other fields; write atomically (temp file + rename) after copying the original to `$HOME/.claude.json.nightwatch-bak` once. `skipped` when already true. A malformed file is `failed`, never overwritten.
  4. `state`: create `$HOME/.local/state/nightwatch/<name>/{specs,dry-specs}` and write `config` (Task 1's keys). `CHECK` is `scripts/check` when the repo has it, else the first `--check-cmd`-generated script path (`scripts/check`).
  5. `switch`: `gh variable get <STATE_VAR>` in the repo. `run` → `skipped`; missing or other → with `--set-switch`, run `gh variable set <STATE_VAR> --body run` (the one place this text appears in code, as an argv array, never a shell string) and re-read; without `--set-switch`, `needs you: run \`gh variable set LANDING_STATE --body run\` in <repo>` and continue (the dry run still works: it reads the switch and stops if it is not `run`, which the step reports).
  6. `check`: `scripts/check` present in the repo → `skipped`. Absent and no `--check-cmd` → `needs you: pass --check-cmd once per CI step (see --report for the lines found in .github/workflows)` and stop before the dry run. Absent with `--check-cmd` lines → write `scripts/check` (bash, `set -uo pipefail`, runs each line in order printing `✓ <line>` or `✗ <line>` and the command's output on failure, ends with `CHECK OK`, mode 755), run it once in the repo and require `CHECK OK` (failure → `failed: scripts/check does not pass on <repo> today: <last line>`; nothing committed), then on branch `nightwatch/init` (created from the current HEAD, or reused) commit it with message `scripts/check: one command that says CHECK OK, for Nightwatch and for people`, push with `-u origin nightwatch/init`, and `gh pr create --fill --base <base>`; record the PR URL. The clone is then fetched again; if the PR is not merged the dry run is still run (it does not need the check), and the status table says `check: PR <url> must merge before a real run`.
  7. `preflight`: `claude`, `gh` (and `gh auth status` exit 0), `jq`, `caffeinate`, `node` on PATH; each missing is `failed`.
  8. `dry-run` (unless `--no-dry-run`): write `<state>/dry-specs/00-plumbing.md` (generic: title `Plumbing check`, `Repo: <name>`, Outcome "the engine can reconcile the branch and run acceptance commands in this clone", Acceptance: `git rev-parse --abbrev-ref HEAD` prints a branch starting with `nightwatch/`; `test -d .git && echo GIT-PRESENT` prints `GIT-PRESENT`; `false` is expected to exit 1; Non-goals: no build, no file change; Context: do not run the repo check for this spec), then run `bash <plugin>/nightwatch/run.sh <name> <state>/dry-specs --dry-run` with stdin from `/dev/null`, capturing the journal tail; `done` when the journal gains `dry run complete`, else `failed` with the last journal line. `--report` lists the lines from `.github/workflows/*.yml` `run:` steps that look like checks (fmt, clippy, test, nextest, lint, typos, machete, deny, xtask) as suggestions for `--check-cmd`.
- Output: a status table (`step  status  detail`) and a last line: `next: /nightwatch:spec` when everything is `done`/`skipped`, or the first `needs you` line. `--json` prints the steps as JSON instead.

- [ ] **Step 1:** write the fixtures and `nightwatch-init.test.mjs`: (a) fresh init on a working repo that has `scripts/check`, fake `gh` (`variable get` → `run`, `auth status` → 0), fake `claude` (as the run fixture, returning DRYRUN), `--clone-root` in the temp HOME → every step `done`/`skipped`, the clone exists with the right origin, `~/.claude.json` (temp HOME) has the trust entry, `config` has all keys, journal has `dry run complete`; (b) running it again → clone `skipped (exists)`, trust `skipped`, nothing else changes, exit 0; (c) repo without `scripts/check` and no `--check-cmd` → `check` is `needs you`, no dry run, exit 1, `--report` output lists the `run:` lines from the fixture workflow; (d) with `--check-cmd "echo one" --check-cmd "echo two"` → `scripts/check` written and passes, branch `nightwatch/init` pushed to the bare origin with one commit, fake `gh pr create` recorded the call (the fixture's `gh` appends its argv to a log file); (e) `--report` on a fresh repo changes nothing (no clone dir, `~/.claude.json` untouched); (f) switch unset and no `--set-switch` → `needs you` with the exact command text, exit 0 when everything else passed; with `--set-switch` the fake `gh` log shows the set call and the step is `done`; (g) a `~/.claude.json` that is not JSON → `trust` `failed`, file untouched, backup absent. Run → FAIL.
